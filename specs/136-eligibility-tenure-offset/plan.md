# Implementation Plan: Correct Employer Contribution Eligibility Service Credit

**Branch**: `136-eligibility-tenure-offset` | **Date**: 2026-08-11 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/136-eligibility-tenure-offset/spec.md`

## Summary

Use `int_workforce_state_accumulator.current_tenure` as the single completed-service value for employer core and match eligibility and for every service-dependent core or match rate decision. Remove later-year and experienced-termination tenure reconstruction from downstream benefit models, preserve the accumulator's termination-date basis and explicit eligibility exceptions, and add strict dbt plus isolated multi-year regression coverage for 0-, 1-, 2-, and 3-year waits. Existing configuration, event, public mart, API, and Studio contracts remain unchanged; rerunning a scenario produces corrected results without migrating saved runs.

## Technical Context

**Language/Version**: Python 3.11; SQL/Jinja compatible with dbt Core 1.8.8 and dbt-duckdb 1.8.1
**Primary Dependencies**: Existing PlanAlign orchestrator, Pydantic v2 configuration, dbt Core 1.8.8, dbt-duckdb 1.8.1, DuckDB 1.0.0, pytest 7.4; no new dependency
**Storage**: Existing scenario-isolated DuckDB workforce, eligibility, contribution, event, and snapshot relations; no new table, persisted field, public mart schema, or result migration
**Testing**: Test-first singular dbt data tests, focused pytest query tests, and isolated multi-year integration simulations using `tmp_path`/`DATABASE_PATH`
**Target Platform**: Local PlanAlign CLI/API simulation engine on macOS and Linux
**Project Type**: Event-sourced workforce and retirement-plan simulation data pipeline
**Performance Goals**: Preserve deterministic single-threaded simulation for 100K+ employees; remove redundant prior-year self-joins from benefit calculations and add no new runtime joins
**Constraints**: Use the current-year workforce accumulator as the authoritative service source; preserve configured exceptions; do not read a current-year `fct_*` mart from an `int_*` model; validate only in isolated databases; keep opening-year and zero-wait results stable
**Scale/Scope**: Core and match eligibility plus service-graded and points-based rate selection across every employee-year in a multi-year projection

## Constitution Check

**Pre-design gate: PASS**

- **Event sourcing & immutability**: No event is added, modified, or deleted. Eligibility and contribution outputs remain deterministic derivations of immutable events, configuration, and accumulated workforce state.
- **Modular architecture**: `int_workforce_state_accumulator` remains the sole workforce-state owner. Eligibility and contribution models consume its current-year value without a reverse dependency on `fct_workforce_snapshot` or a new accumulator.
- **Test-first development**: Strict service-basis dbt tests and isolated multi-year regression fixtures are specified before the production SQL change.
- **Enterprise transparency**: Eligibility `current_tenure` and contribution `applied_years_of_service` must reconcile exactly to the workforce record; existing reason codes and exception metadata remain available for audit.
- **Type-safe configuration**: No configuration field changes. Existing validated Pydantic settings continue to export the same dbt variables.
- **Performance & scalability**: The correction removes prior-year self-joins and downstream tenure reconstruction, adding no tables, joins, or per-employee state.

**Post-design gate: PASS** — the design establishes one existing accumulator field as the internal contract, keeps the pipeline build order intact, adds strict automated reconciliation, and introduces no constitutional exception.

**Structure Decision**: Correct the three existing downstream benefit models at their current ownership boundaries. The workforce accumulator and tenure macro already implement the required annual/termination-date service rule, so they are contract providers rather than change targets. Focused dbt tests enforce each build year, while an independent integration module owns the multi-run cost comparison without expanding the already budget-capped Feature 124 edge matrix.

## Implementation Approach

1. Add failing singular dbt tests that require `int_employer_eligibility.current_tenure`, core `applied_years_of_service`, and match `applied_years_of_service` to equal `FLOOR(int_workforce_state_accumulator.current_tenure)` exactly on the scoped employee/year key. Add fast synthetic query tests that prove a deliberate one-year offset and a wider reset/termination offset are detected. Tighten the existing match audit tolerance so a one-year drift fails.
2. In `int_employer_eligibility`, project the current-year accumulator tenure directly and remove the prior-year self-join and `+ 2` override. Keep hour, active-at-year-end, new-hire, and termination-exception logic unchanged.
3. In both contribution calculations, select service and points tiers from that same current-year accumulator tenure. Remove experienced-termination and prior-year tenure reconstruction while preserving compensation proration, status exceptions, formulas, caps, and reason codes.
4. Update `schema.yml` descriptions/tests to name the canonical basis, add a singular requirement-enforcement test for configured core and match waits, and strengthen the pipeline graph contract so downstream benefit models cannot regain prior-year service arithmetic.
5. Add a deterministic, small-census, five-year isolated regression suite for 0-, 1-, 2-, and 3-year core waits plus enforced match eligibility. Capture a pre-fix characterization JSON for opening-year and zero-wait outputs, assert non-vacuous boundary cohorts, compare annual costs across waits, cover a mid-year termination and reset/broken-service record, and assert that the shared dev database is unchanged.
