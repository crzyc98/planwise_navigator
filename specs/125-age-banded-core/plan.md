# Implementation Plan: Age-Banded Employer Core Contributions

**Branch**: `125-age-banded-core` | **Date**: 2026-07-30 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/125-age-banded-core/spec.md`

## Summary

Add `age_banded` as a fourth employer core contribution shape. A plan-owned age schedule will be validated at configuration load, retained through both configuration export paths, and evaluated once per employee per simulation year from the workforce accumulator’s `current_age`. A single rendered core-rate expression will drive both the monetary calculation and audit rate so all existing modes remain deterministic and internally consistent. Studio configuration, read-only plan details, comparison copy, and the existing 401(a)(4) review surface will present the design accurately.

**Scale/Scope**: One new plan-design rate shape across core config validation, dbt export/calculation, Studio editing/summaries, 401(a)(4) caveat, fixtures, and regression coverage

## Implementation Approach

1. Define the validated `age_schedule` / `core_age_schedule` contract and add load-time Pydantic validation for non-negative ages and rates, contiguous `[min, max)` ranges, no overlaps, and a final open-ended tier when a nonempty age-banded schedule is supplied. Preserve the specified empty-schedule flat-rate fallback.
2. Export the direct YAML and Studio `dc_plan` schedules as `employer_core_age_schedule`, converting decimal configuration rates to macro percentages exactly once.
3. Add a standalone age-banded core-rate macro that checks explicit minimum and maximum bounds. In the core-contribution model, hoist rate selection into one Jinja expression and reuse it for the amount and audit-rate columns. Continue using `snap.current_age` as the annual point-in-time driver.
4. Extend Studio form types, defaults, loading, payload serialization, editor, plan modal, and comparison text using existing core tier patterns. Add an accurate generic nondiscrimination-review warning for the existing 401(a)(4) surface when core mode is age-banded.
5. Add focused unit, dbt/model, and isolated multi-year integration coverage, including exact tier boundaries, an age migration across years, a mid-year-hire compensation basis, output rate/amount consistency, and unchanged existing core modes.
