# Studio configuration field inventory

Evidence and wording contract for [#863](https://github.com/crzyc98/planwise_navigator/issues/863) and [#866](https://github.com/crzyc98/planwise_navigator/issues/866), under epic #862. Audited 2026-10-15. This inventory distinguishes persistence, exported engine inputs, and measured outcomes; an export test alone does not establish an outcome.

## Read and save contract

The editable controls are defined in `planalign_studio/components/config/types.ts`. `ConfigContext.tsx` projects persisted configuration into those controls; `constants.ts` supplies initial form fallbacks, not authoritative engine defaults. `buildConfigPayload.ts` converts edited values to the Studio API shape. Preserve original configuration and apply only actual edits: rebuilding a complete config from displayed defaults changes inherited settings, inactive schedules, and keys the form cannot represent.

Workspace configuration is persisted in `base_config.yaml`; scenario `config_overrides` are persisted in scenario JSON/YAML by `WorkspaceStorage.update_scenario`. Updates replace the supplied override object. `WorkspaceStorage._merge_config` recursively merges workspace and scenario values, replaces lists, and treats `promotion_hazard`, `age_bands`, and `tenure_bands` atomically. It also resolves match-response settings and injects missing seed defaults. Therefore an unchanged scenario save must retain the original override object, not save the entire merged view.

`SimulationService._prepare_simulation` resolves the census, writes the merged `config.yaml`, and calls `write_seeds`. The seed order is repository defaults → applied parameter-pack seeds → configured promotion hazards/bands. `prepare_dbt_project` creates a run-local project overlay. `build_command` invokes the production CLI with that config, an explicit run-local database, and that project. `load_simulation_config` normalizes typed fields; `config/export.py::to_dbt_vars` supplies dbt inputs. A saved key can survive this entire path without affecting either exported variables or seed files.

Use independent indicators: **inherited** (absent from scenario overrides), **overridden** (present), **changed** (different from the loaded value), **inactive** (its enabling condition is false), and **mapping unverified** (no demonstrated engine path). “Default” must name its source: loaded workspace/scenario, legacy engine section, typed model, shipped seed, or initial Studio fallback. Never infer inheritance from equality with `DEFAULT_FORM_DATA`.

`resolvedFormData.ts::applyResolvedFormData` projects the backend's exported variables over the raw form projection, so legacy inputs display their resolved values instead of initial Studio defaults. It preserves source selectors and unsupported/helper fields. Decimal rates are converted once, percentage-valued schedule rates remain percentages, and null bounds remain open-ended. Verified SQL/project fallbacks cover omitted global contribution and escalation variables: absent core service requirement means **one year**, not the Studio zero-year fallback; absent core rate means **2%** at the SQL layer unless storage/config exports another rate. `int_employer_eligibility` reads nested eligibility, not flat core aliases. The plan enrollment wait reads `plan_eligibility_waiting_period_days` (default zero), not the similarly named legacy eligibility variables. The projection is display state, never a replacement for original persisted configuration. `fixtures/resolvedEngineInputs.json` is checked against the real Python exporter by a fast test and consumed by frontend unit tests. An eligibility wait not divisible by 30 must retain its exact-day explanation; a displayed month equivalent does not authorize truncating an unchanged legacy value.

## Units and evidence notation

- **Mapped** means a specific exported variable or seed and reachable consumer were located. It is source/export evidence, not a new outcome validation of every combination.
- **Ineffective** means saved values do not reach consumed inputs on the audited production path. The bounded A/B evidence below scopes the outcome claim.
- **Helper** means analysis input/result or metadata; it is not an independent simulation constraint.
- **Unverified** means preservation is required but this audit does not establish the setting's effective behavior.
- `% → fraction` means divide the displayed value by 100 exactly once; `pp` means percentage points, not a fraction. Booleans, zero, `null`, missing keys, and blank text are different states. Keep `null` schedule maxima open-ended. Bands use `[min, max)`; legacy service-year core schedules retain their existing inclusive bounds and export conversion.

Unless specified otherwise, defaults are **loaded value first, Studio fallback second**; the fallback column below documents initial form values, not an instruction to write them during a save. Population and activation columns describe the intended mapped consumer, not a compliance guarantee.
